# Медицинские формы и персональные данные

Сайт обрабатывает ПД пациентов (152-ФЗ). Отзывы и заявки могут содержать данные о здоровье — это специальная категория.

## Где уже реализовано (переиспользуй, не дублируй)
- Согласие: `'consent' => ['accepted']` + сообщение «Необходимо согласие на обработку персональных данных.» — `BookingController`, `LeadService::validate`, `Api/AssistantController`. Сохраняется `consent_at`.
- Фильтр чувствительного текста в отзывах/сообщениях: `App\Services\SensitiveTextGuard` (`blockingMessage`, `reviewFlags`).
- Лимиты: `throttle:leads`, `throttle:auth` в `routes/web.php`.
- Клиентские поля и ошибки: `resources/js/components/ui/Fields.tsx`; модалка заявки `LeadModal.tsx`; отзыв `ReviewForm.tsx`.

## Обязательно
1. Валидация всегда на сервере; клиентская — только подсказка. Новые правила — в том же стиле, что соседний код (inline `validate()` / сервис), с русскими сообщениями.
2. Любая публичная форма с ПД: чекбокс согласия (не отмечен по умолчанию, ссылка на политику), `throttle`, сохранение `consent_at`.
3. Собирай минимум полей. Телефон нормализуй к одному формату перед сохранением.
4. ПД не попадают в: URL/query, логи (`Log::`), `AnalyticsEvent`, Sentry-контекст, тексты уведомлений в публичные каналы, Inertia-props страниц, где они не нужны.
5. Доступ к лидам/записям — только сотрудникам своей организации (проверка по organization), админам — по ролям. Любое новое действие с ПД — через `Audit` (как в соседних контроллерах).
6. Отзывы и посты клиник проходят модерацию; телефон/ФИО/диагнозы в тексте блокируются или маскируются через `SensitiveTextGuard`.
7. Изменения профиля клиники из ЛК не публикуются напрямую — только через модерацию (см. «Бизнес-правила» в `PROJECT_MAP.md`).

## UX форм (особенно мобильная версия)
- `inputmode="tel"` / `autocomplete` для телефона и имени, поле ≥44px, подписи над полем, а не только placeholder.
- Ошибка — рядом с полем и понятная; кнопка отправки блокируется на время запроса; после успеха — явное подтверждение и что будет дальше.
- Не сбрасывай введённые данные при ошибке сервера.

## Тесты
На каждое изменение формы — feature-тест: успешная отправка, отказ без `consent`, ошибки валидации, доступ чужой организации → 403/404. Используй фабрики.
