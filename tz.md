# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## Веб-платформа поиска стоматологических клиник, врачей и онлайн-записи по России

---

# 1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

Необходимо разработать и запустить единую веб-платформу для поиска стоматологических клиник, врачей и стоматологических услуг по городам России.

Платформа должна одновременно решать три задачи:

### Для пользователей

Позволять быстро найти стоматологию, врача или необходимую услугу, сравнить предложения, изучить цены и отзывы и записаться на приём.

### Для стоматологических клиник

Предоставлять личный кабинет для размещения и управления клиникой, филиалами, врачами, услугами, ценами, расписанием, записями пациентов, отзывами, рекламой и статистикой.

### Для владельца платформы

Предоставлять административную систему для управления всем сервисом, пользователями, клиниками, тарифами, рекламой, платежами, контентом, аналитикой, отчётностью и настройками.

Платформа должна быть рассчитана на работу по всей России и возможность дальнейшего масштабирования.

---

# 2. ОСНОВНАЯ БИЗНЕС-МОДЕЛЬ

Платформа предоставляет пользователям бесплатный доступ к поиску стоматологий и врачей.

Основная монетизация осуществляется за счёт клиник.

Клиники могут оплачивать:

- размещение на платформе;
- тарифные планы;
- поднятие карточки;
- приоритетное размещение;
- размещение в блоках рекомендаций;
- рекламные баннеры;
- дополнительные рекламные возможности.

Все цены, тарифы, сроки и правила размещения должны управляться администрацией платформы.

---

# 3. ОСНОВНЫЕ РОЛИ

Система должна предусматривать следующие роли.

## 3.1. Гость

Пользователь без авторизации.

Может:

- выбирать город;
- пользоваться поиском;
- просматривать клиники;
- просматривать врачей;
- смотреть услуги;
- смотреть цены;
- читать отзывы;
- использовать фильтры;
- открывать карточки клиник и врачей.

---

# 4. ЗАРЕГИСТРИРОВАННЫЙ ПОЛЬЗОВАТЕЛЬ

После авторизации пользователь получает личный кабинет.

Пользователь может:

- управлять профилем;
- записываться на приём;
- просматривать свои записи;
- отменять запись;
- переносить запись, если это разрешено;
- добавлять клиники в избранное;
- добавлять врачей в избранное;
- оставлять отзывы;
- видеть историю отзывов;
- получать уведомления;
- видеть историю посещений и взаимодействий с платформой.

---

# 5. КЛИНИКА

Клиника получает отдельный личный кабинет.

Через него она может:

- управлять организацией;
- создавать филиалы;
- редактировать филиалы;
- добавлять врачей;
- управлять врачами;
- добавлять услуги;
- устанавливать цены;
- создавать расписание;
- управлять онлайн-записью;
- работать с пациентами;
- отвечать на отзывы;
- публиковать акции;
- покупать тариф;
- покупать продвижение;
- покупать рекламные места;
- загружать баннеры;
- смотреть статистику;
- видеть платежи;
- видеть срок действия оплаченных услуг.

Россия  
→ Регион  
→ Город  
→ Район  
→ Клиника / филиал.

Администратор должен иметь возможность:

- связывать районы с городами;
- активировать или отключать города.

# 9. ВЫБОР ГОРОДА

При первом посещении пользователю предлагается город.

Пользователь может:

- принять предложенный город;
- выбрать другой;
- найти город через поиск;
- изменить город в любой момент.

Выбранный город сохраняется.

Все каталоги и результаты поиска должны автоматически учитывать выбранный город.

# 22. ОНЛАЙН-ЗАПИСЬ

На платформе должна работать полноценная система бронирования времени.

Пользователь проходит путь:

Выбор клиники  
→ выбор филиала  
→ выбор услуги  
→ выбор врача  
→ выбор даты  
→ выбор свободного времени  
→ подтверждение записи.

---

# 23. РАСПИСАНИЕ

- исключения;

---

# 24. ЗАЩИТА ОТ ДВОЙНОЙ ЗАПИСИ

Система не должна позволять двум пользователям записаться к одному врачу на одно время.

Если слот уже занят, он должен немедленно становиться недоступным.

---

# 25. СТАТУСЫ ЗАПИСИ

Запись должна иметь статусы.

Например:

- новая;
- ожидает подтверждения;
- подтверждена;
- перенесена;
- выполнена;
- отменена;
- пациент не пришёл.

Администратор клиники меняет статусы из личного кабинета.

---

- отменить запись.

История изменений должна сохраняться.

Это повышает доверие к рейтингу.

- отклонена;
- скрыта;
- заблокирована.

**Подключает клиники → управляет сервисом → контролирует качество → продаёт тарифы и рекламу → получает платежи → анализирует показатели → развивает новые города.**

Главный принцип проекта:

**основное управление платформой, клиниками, контентом, тарифами, рекламой, платежами и аналитикой должно выполняться через интерфейс системы без необходимости обращаться к разработчику для ежедневных операций.**
